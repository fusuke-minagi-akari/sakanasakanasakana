# /overnight — 夜間自律実装ループ

`$ARGUMENTS`: 初回はゴール文 or タスクリストファイルパス。2回目以降は空でよい（状態はファイルに残る）。

**`/loop /overnight <goal>` から呼ばれる前提。絶対に質問しない。** 迷ったら安全側（そのタスクをスキップ、または重大なら停止）に倒す。

state: `.claude-overnight/`（リポジトリ直下。無ければ `.gitignore` に追記推奨）
- `TASKS.md` — チェックリスト
- `RUN_LOG.md` — 1行1エントリの進捗ログ（追記のみ、消さない）
- `BLOCKED.md` — 重大ブロッカーでループ停止した時だけ作成
- `REPORT.md` — 全完了時だけ作成、朝読む用

## 0. 事前チェック（`.claude-overnight/` が無い＝初回起動時のみ）

- git repo でない → 質問せず `BLOCKED.md` に理由を書いて即 `ScheduleWakeup({stop:true})`。取り消せる保証（git履歴）が無い状態で一晩回さない
- 専用ブランチを切る: `overnight/<YYYYMMDD>-<slug>`。**元にいたブランチには絶対コミットしない**（uncommitted changesがあってもブランチ作成でそのまま持ち越されるので問題ない）
- `$ARGUMENTS` がファイルパスならその内容を `TASKS.md` にコピー。自由文のゴールなら**今すぐ**具体的なチェックリストに分解して書く（後回しにしない）
- `$ARGUMENTS` に `--dry-run` があれば: 分解したチェックリストをチャットに出力するだけで**ここで終了**（ブランチ切らない、コミットしない、`.claude-overnight/`も作らない、1.に進まない、ScheduleWakeupも呼ばない）。本番前にゴール分解の妥当性を人間が確認するためのモード
- `RUN_LOG.md` に開始時刻とゴールを1行
- ここまでをコミット
- **セットアップだけで turn を終えない。** そのまま同じターンで下の 1. に進み、最初のタスクに着手する

## 1. 毎回起動時（ステディステート）

1. `TASKS.md` の先頭の未チェック項目を1つ取る。無ければ → 3. 完了処理へ
2. 実装する。既存コードの規約に従う。過剰な抽象化・先回りの汎用化はしない
3. そのタスクに関連するテスト/lint/buildを実行する
4. 成功 → チェックを付ける、コード+チェックを意味のあるコミットメッセージでコミット。**shaはコミット後でないと分からない**ので、コミット→`git log -1 --format=%H`でsha取得→`RUN_LOG.md`に1行追記（時刻・タスク名・commit sha・要点）→ログだけの小さいコミット、の順で行う
5. 3回試して直らない → チェックは付けず該当項目に `(blocked: 理由)` を追記、`RUN_LOG.md` に `BLOCKED-TASK:` 行を書き、**そのタスクだけ諦めて次へ進む**（ループ全体は止めない）
6. 4.か5.のあと、TASKS.mdの残り未処理項目をチェックする:
   - まだ残っている → **必ず `ScheduleWakeup` を呼んでループを継続する**（呼ばないとここでループが無言で終わる、自動継続はしない）
     - `prompt`: 元々の `/loop` 入力を**`/loop `を付けて**そのまま（例: `/loop /overnight <goal>`）。`/loop`無しで`/overnight`だけ渡すと次回`/loop`の再アーム処理を経由しなくなるので必須
     - `delaySeconds`: 60（外部要因を待っているわけではなく次のタスクに即着手したいだけなので最小値）
     - `noop`: false（コミットした/ログを書いた＝進捗あり）
     - `reason`: 一言で次にやることを書く
   - 今処理したのが最後の項目だった（残り0件） → `ScheduleWakeup`は呼ばず、**同じターンのまま 3. 完了処理へ**進む（空になったことを確認するためだけに次の起動を待たない）

## 2. ループ全体を止める重大ブロッカー（このカテゴリだけ）

- 認証情報/APIキーが無くて進めない
- スキーマ破壊的変更（DBマイグレーション等）で人間の判断が要る
- 解消できない merge conflict

該当したら `.claude-overnight/BLOCKED.md` に理由を書き `ScheduleWakeup({stop:true})`。個別タスクの失敗（1.の5.、push/PRが要るタスクも含む）はここに含めない＝そのタスクだけ諦めて1.の6.でループ継続する。

## 3. 完了処理

`TASKS.md` 全項目が処理済み（チェック or blocked注記）になったら:
- `.claude-overnight/REPORT.md` を書く。構成: やったこと(箇条書き) / 積んだコミット一覧 / ブロックされた項目と理由 / 次にやるべきこと。**人間が朝1分で読める密度**にする
- `ScheduleWakeup({stop:true})`

## 4. 絶対にしないこと

- push, force-push, PR作成, 元のブランチへの直接コミット
- credential が要る操作を人間の確認なしに進める
- ユーザーに質問する（`/loop` から呼ばれている＝誰も見ていない前提）

## 使う前の前提条件

初回利用前に `/fewer-permission-prompts` を一度流すこと。git/test コマンドが許可リストに無いと、夜間に許可プロンプトで**無言stall**する（既知の失敗パターン、エラー無しでそのまま止まる）。
