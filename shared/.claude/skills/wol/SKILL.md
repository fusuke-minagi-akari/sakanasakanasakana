# /wol — セッションを WoL スレッドにする

WoL = 作業を Slack スレッドで実況し、周りが状況を把握・助言できるようにする社内文化。親メッセージ(`wol: <トピック>`。他の人は `[wol] <トピック>` も使う)を立て、返信で進捗を積む。

`$ARGUMENTS` = 投稿先 + 任意でトピック(Codex では利用者の発言から読む)。

## 1. 引数を解釈

- **スレッドURL**(`https://*.slack.com/archives/<CHANNEL>/p<digits>[?thread_ts=<ts>]`)→ 既存スレッドに追記。
  - channel = `<CHANNEL>`
  - thread_ts = `thread_ts` パラメータがあればそれ(スレッド内の返信へのリンク)。無ければリンク先が親なので、`p` の数字の後ろ6桁の前に `.` を入れたもの(`p1234567890123456` → `1234567890.123456`)
- **チャンネルだけのURL**(`/archives/<CHANNEL>` で `p...` 無し)→ そのチャンネルに新規スレッド
- **`#name` / `C...`** → そのチャンネルに新規スレッド。名前は `slack_search_channels` で ID に解決
- **`U...`(user ID)** → その人との DM に新規スレッド(自分の ID なら自分 DM = テスト用)
- **何も無い** → `slack_search_public_and_private` で `from:<@自分のID>`(このツールの説明に「Current logged in user's user_id」として載っている)の最近の `wol:` / `[wol]` 親メッセージを検索し、使っているチャンネル上位3つを選択肢にしてユーザーに聞く。見つからなければ投稿先を聞く
- 残りの文字列 = トピック(省略時はセッション内容から短く付ける)

## 2. 既存スレッドなら先に読む

`slack_read_thread` で全件読み、**既に書かれていることは投稿しない**(差分だけ)。相手の質問が残っていれば、答えられるものは返信に含める。

## 3. セッションから素材を拾う

このセッションの会話・ツール結果から、他の人が読んで意味があるものだけ:

- やったこと / 分かったこと(数値は N・条件付き)
- 詰まった点とその原因、効かなかったこと
- 成果物リンク: PR・commit・branch・Notion・artifact の URL(ローカルパスは読み手に無意味なので、URL が無ければ1行で名前だけ)
- 決めたこと・未決のこと
- 次にやること(NA)と担当

拾わない: 試行錯誤の細かい手順、ツール出力の貼り付け、秘密情報(token・パスワード・鍵)、`~/.claude/CLAUDE.md` の機密情報フィルター対象(クライアント企業名・金額・AWS ID・NDA 事項)。

## 4. 書き方(実際の WoL スレッドに合わせる)

- **親**: `wol: <トピック>`(1行。関係者がいれば `cc <@U...>`)
- **言語**: 日本語(セッションが英語でも。コード・識別子・固有名詞はそのまま)
- **返信**: 1投稿 = 1トピック。短く、話し言葉、時系列。目安 3〜10 投稿
  - 例: `最速更新(N=1)` / `キャッシュ切ったら失敗。うーん。`
  - 箇条書きは `•`、ネストは `◦` 相当のインデント
  - 相手の発言に答えるときは `> 引用` の次の行に答え
  - リンクは単体で置き、次の行に一言説明
- **最後の返信**: NA リスト
  ```
  NA
  • <やること>：<担当>
  ```
- メンションは、セッション中に名前が出た人で通知が必要な人だけ `slack_search_users` で ID を引いて `<@U...>`。推測で付けない
- 人には性別表現を使わない(名前で呼ぶ)
- 1投稿 5000 文字以内。日本語の推敲ルール(`yomiyasu`)は適用外(WoL は砕けた実況でよい)

## 5. 確認 → 投稿

1. 下書き全体(親 + 返信を番号付き)と投稿先をユーザーに見せ、「送る?」と聞く。**承認なしで送らない**
2. Slack ツールがある場合(Claude Code): `slack_send_message`
   - 新規: 親を送る → 返り値の `message_context.message_ts` を thread_ts、`message_context.channel_id` を以降の channel_id にして返信を順に送る(DM を user ID で送ると channel_id が `D...` に変わる)
   - 追記: 全部 thread_ts 付きで送る
   - `reply_broadcast` は使わない
   - 投稿者は利用者本人(「Claude を使用して送信」ラベル付き)。チャンネルに Claude アプリを入れる必要は無い(2026-10 確認済)
   - 途中で失敗したら、再送前に `slack_read_thread` で届いた分を確認し、残りだけ送る(二重投稿しない)
3. Slack ツールが無い場合(Codex 等): `mkdir -p ~/Desktop/claude-outputs/wol` して下書きを `~/Desktop/claude-outputs/wol/<YYYY-MM-DD>-<topic>.md` に書き、`pbcopy` でクリップボードへ。投稿は手動と伝える(sandbox が書き込みを拒否したら、下書きをそのまま表示する)
4. 最後にリンクを返す: 新規は親の送信結果の `message_link`、追記は渡されたURL。Slack ツールが無い場合は書いたファイルのパス
