# /sanitize — レポートの機密情報除去

## ファイル読み込み

以下の順序でファイルを探す:
1. `~/Desktop/claude-outputs/reports/$ARGUMENTS`
2. `~/Desktop/$ARGUMENTS`
3. 上記に `.md` を付けたパス
4. いずれも見つからなければ `~/Desktop/claude-outputs/reports/*.md` と `~/Desktop/*.md` を一覧表示してユーザーに確認。

## 匿名化プロセス

以下の10カテゴリを**順番に**処理する。各カテゴリで文書全体をスキャンし、該当箇所を置換。カテゴリ毎の置換数を記録する。

### カテゴリ1: ローカルパス

**検出:** `/Users/...`, `/home/...`, `/workspace/...`, `/var/...`, `/opt/...`, `/tmp/...`, `~/...`, `C:\...`

**置換:** ユーザー固有プレフィックスを除去。汎用的な相対パス (`./`, `../`, `[path]/`) に置換。コードブロック内は `./project/`, `./src/`, `./data/` 等の汎用パスに。

### カテゴリ2: リポジトリ・ブランチ名

**検出:** GitHub URL (`github.com/...`)、gitリモートURL、ブランチ名 (`branch: feature-xxx`、`ブランチ: xxx`)、リポジトリ名。

**置換:** `[リポジトリ]`、`[ブランチ]`、またはURL自体を削除。`gh` コマンド例示の場合は `org/repo` に置換。

### カテゴリ3: 組織・会社名

**検出:** 会社名（日本語・英語）、チーム名、部署名、GitHub URLの組織名、メールドメイン。

**置換:** 削除または `[組織]`。メールドメインは `@example.com`。

### カテゴリ4: 人名

**検出:** 著者行 (`著者:`, `Author:`)、日本語名（例: 田中 太郎）、英語名、メールアドレス、GitHub @ハンドル、`Co-Authored-By` 行。

**置換:** 行ごと削除、または `[担当者]`。部分的な名前を残さないこと。

### カテゴリ5: ホスト名・IPアドレス

**検出:** マシンホスト名（例: `server-01.local`）、IPアドレス (`192.168.x.x`, `10.x.x.x`)、内部ドメイン名。

**置換:** `[デバイス]` または `[サーバー]`。

### カテゴリ6: タスク固有の対象物

**最も重要かつ繊細なカテゴリ。** システムが操作する対象物（製品、欠陥種別、物体クラス、材料等）の具体名はプロジェクト目的を暴露する。

**検出箇所:**
- セクション見出し
- データセット説明
- メトリクス説明
- コードブロック内のプロンプトテキスト
- コードスニペット内の変数名（例: `defect_count`）

**置換:** カテゴリレベルに汎化:
- 具体的な物体 → "対象物"
- 具体的な欠陥 → "対象の状態"
- 具体的な動作 → "対象タスク"
- 検出タスク → "検出・分類タスク"

**徹底する:** コードブロック、JSON例、ログ抜粋、テーブルセル内も確認。タスク対象物はあらゆる場所に潜む。

### カテゴリ7: データセット詳細

**検出:** 正確なファイル数 (`36枚`, `1000 images`)、画像寸法 (`4096x2304`)、日付入りディレクトリ名 (`20260331_...`)、ファイル命名パターン (`1.JPG`, `sample_001.png`)、データセット名。

**置換:** `N枚`、`[解像度]`、`[データセット]`。相対比率が重要な場合は比率を維持し絶対数を除去。

### カテゴリ8: モデル名（公開・内部とも全て）

**検出:** 全てのモデル識別子:
- HuggingFace ID (`Qwen/Qwen3-VL-2B-Instruct`, `meta-llama/...`)
- 短縮名 (`Qwen3-VL-2B`, `GPT-4`, `Gemma`)
- バージョン接尾辞 (`-Instruct`, `-Chat`, `-Base`)
- 内部/独自モデル名

**置換:** サイズクラスのみ:
- < 3B → "小型VLM/LLM (2Bクラス)"
- 3-10B → "中型VLM/LLM (7-9Bクラス)"
- 10-30B → "大型VLM/LLM (20Bクラス超)"
- > 30B → "超大型LLM (70Bクラス超)"
- サイズ不明 → "VLM" or "LLM"

モデルの種類（VLM vs LLM vs embedding）は維持。具体名を除去。

### カテゴリ9: 内部URL

**検出:** Jira/Linear/Notion/Confluence リンク、Slack チャンネル参照、内部wiki URL、プライベートGitHubリポジトリURL、内部ダッシュボードURL。

**置換:** 完全削除、またはコンテキスト上必要なら `[内部リンク]`。

### カテゴリ10: ハードウェア識別子

**検出:** 具体的なチップ名 (`Apple M5`, `Jetson AGX Orin`, `RTX 4090`)、GPU型番、マシン特定につながるRAM量、特定ハードウェアに紐づくCUDAバージョン。

**置換:**
- Apple Silicon系 → "Apple Silicon"
- Jetson系 → "エッジデバイス (ARM)"
- GPU型番 → "GPU"
- 具体的なメモリ量 → "十分なメモリ"
- CUDAバージョン → 削除または "対応CUDAバージョン"

## 保持するもの（置換しない）

- **手法の説明** — 技術、アルゴリズム、パイプライン設計
- **数値結果** — パーセンテージ、F1、IoU、accuracy、コスト、時間
- **コード構造パターン** — アーキテクチャ判断、ファイル構成（内部の名前は置換）
- **公開ツール/フレームワーク名** — PyTorch, transformers, Docker, Claude Code
- **レポートの構造** — 見出し、テーブル、流れ
- **汎用技術用語** — "zero-shot", "few-shot", "ICL", "two-stage inference"

## 保存

出力先: `~/Desktop/claude-outputs/sanitized/<出力ファイル名>`

ファイル名の生成:
- 入力: `report_20260408_foo.md` → 出力: `report_20260408_foo_sanitized.md`
- 入力: `my_report.md` → 出力: `my_report_sanitized.md`

ディレクトリが存在しない場合は `mkdir -p` で作成。元ファイルは変更しない。

## 機密情報レビュー（最終ステップ）

保存後、**新しいAgent**を起動して匿名化済みファイルをレビューさせる。このAgentはプロジェクトの知識を一切持たない。

Agentへのプロンプト:
```
あなたはセキュリティレビュアーです。以下のマークダウンレポートが他部署のエンジニアに
共有されます。読者が以下を特定できてはいけません:
- 具体的な会社、チーム、組織
- 具体的な製品、プロジェクト、ビジネス目標
- 検出/分類/構築している具体的な対象物
- 内部インフラ（サーバー、リポジトリ、ホスト名、IP）
- 個人の身元

ただし以下は許容（機密ではない）:
- 公開AIモデル名（Claude, Opus, Sonnet, GPT-4等）
- 公開ツール名（PyTorch, Docker, Claude Code等）
- 日本円表記（JPY）や日本語

~/Desktop/<ファイル名> を読み、全行をスキャンしてください。

問題がある行ごとに:
  LINE <行番号>: "<該当テキスト>" — リスク: <何が漏洩するか>

問題ゼロの場合: "PASS — 機密情報は検出されませんでした。"
問題がある場合: 全て列挙した後 "FAIL — <件数>件の問題が見つかりました。"
```

**FAILの場合:**
1. 発見内容をユーザーに表示
2. 確認: "自動修正しますか？ (y/n)"
3. yesなら: 各フラグ行を汎化し、再保存、レビュー再実行
4. noなら: そのままにして警告を記載

**PASSの場合:**
- "✅ 機密情報レビュー通過" と表示
