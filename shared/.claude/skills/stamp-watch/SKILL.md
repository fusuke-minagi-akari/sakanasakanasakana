# /stamp-watch — チャンネル監視型スタンプ

`$ARGUMENTS`: channel ID（省略時は設定ファイルの `default_channel_id`）/ `--dry-run` / `--max N`（既定5）

設定: `~/.claude/scripts/stamp_watch_config.json`（`default_channel_id` / `default_channel_name` / `self_user_id`）。無ければユーザーに作成を促す（`shared/.claude/scripts/stamp_watch_config.example.json` がテンプレート）。

**`/loop` から呼ばれる前提。絶対に質問しない。** 判断に迷ったら押さずにスキップして次へ。

自分 = 設定の `self_user_id`。**自分の投稿には押さない。**

## 1. 前回位置を読む

```bash
W=~/.local/state/slack-stamp/<CH>.watch; mkdir -p "$(dirname $W)"; cat "$W" 2>/dev/null || echo 0
```

値が `0`（初回）なら **直近1件だけ**を対象にする。過去全部に押さない。

## 2. 対象を集める

1. `slack_read_channel(channel_id, limit=50, response_format="detailed")`
   **直近50件のみが対象範囲。** それより古いものは前回位置に関係なく見ない（取りこぼしは許容する）。
2. 各メッセージについて:
   - `Message TS` > 前回位置 かつ 投稿者が自分でない → **対象**
   - `Thread: N replies (latest: ...)` があり latest が前回位置より新しい → `slack_read_thread(channel_id, 親TS)` を読み、**前回位置より新しい他人の返信**を対象に追加
3. 既に自分が押したか不明なメッセージは、そのメッセージの Reactions 欄だけでは判定できない。**前回位置より新しいものだけ**を扱うことで二重押しを防ぐ（位置は必ず最後に更新する）。
4. 対象が0件 → `nothing new` とだけ出力して**即終了**（ここで余計なツールを呼ばない＝コスト削減の要）
5. 対象が `--max N` 件を超える → **新しい順に N 件**だけ処理

## 3. スタンプを選ぶ

語彙は **read_channel / read_thread の Reactions 欄**（＝そのチャンネルで実際に使われている絵文字＝文化）を一次ソースにする。これで足りるなら `slack_search_emojis` を呼ばない（1回でも呼ぶとコストが跳ねる）。

本文に強い固有名詞があり手持ち語彙に合うものが無い時のみ、`slack_search_emojis` を**1回だけ**、カンマ区切りで複数語まとめて引く。ローマ字とかな/漢字の両方を含める（`:ギャル:` `:完全に_理解した:` のように絵文字名が日本語のものがある）。

選定基準:
- **本文固有のフック > 汎用の褒め。** そのメッセージにしか押せないものが理想
- **既に付いている絵文字は選ばない。** 呼ばれるたびに違うものを1個足す
- **1回の実行につき1メッセージ1個。**

### 同じメッセージへの再押下（上限あり）

「既に押したからスキップ」はしない。ただし**自分が既に2個押しているメッセージには押さない**。
取り消せない以上、1メッセージに自分のスタンプが無制限に積み上がるのを防ぐため。
判定は Reactions 欄では不可（誰が押したか出ない）→ **位置ファイルより新しいものだけ扱う**運用で代用し、
明示的に同一メッセージを指定された時のみ2個目を許可する。

押さない条件（迷ったらスキップ）:
- ネガティブな内容（障害・失敗・体調不良）に笑い系
- 攻撃的・皮肉に読めるもの
- 人物の性別を推定するもの
- 語彙に確証が持てない絵文字名（**存在しない名前を押すと失敗する**）

## 4. 押す・位置を更新する

### `--dry-run` の時（厳守）

**押さない。位置ファイルに書き込まない。`echo > ...watch` を実行してはいけない。**
候補を出力したら**そこで終了**する。「位置は変えていない」と報告するだけで実際に書くのは違反。
（実測で、この指示が緩い時に dry-run が位置を進めてしまい、間のメッセージが永久に取りこぼされた）

通常時: `slack_add_reaction(channel_id, ts, emoji)` をメッセージごとに実行。
`already_reacted` エラーは無視して次へ。それ以外のエラーはそのメッセージを飛ばす。

最後に**必ず**位置を更新（1件でも処理したら）:

```bash
echo "<処理した中で最大のTS>" > ~/.local/state/slack-stamp/<CH>.watch
```

失敗して途中で終わった場合も、**成功した分までの最大TS**を書く。書かないと次回に二重押しする。

## 5. 出力

1メッセージ1行。前置き・要約・所感を書かない。

```
:選んだスタンプ: ← <投稿者>: <本文20字>
nothing new
```

## 注意

- **リアクションは API で取り消せない**（`remove_reaction` は存在しない）。確信が無ければ押さない
- `slack_add_reaction` は**対話セッションでのみ利用可能**。`claude -p` では存在しないため /loop は対話セッションで回すこと
