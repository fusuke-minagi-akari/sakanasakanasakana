## 出力ディレクトリ規約

非リポジトリ出力は全て `~/Desktop/claude-outputs/` 配下。

```
~/Desktop/claude-outputs/
├── reports/       ← /report で生成したレポート
├── sanitized/     ← /sanitize で匿名化したレポート
└── <新規カテゴリ>/  ← 新しいスキルの出力は適切なサブディレクトリを作成
```

- リポジトリ成果物（コード・テスト・設定）→ リポジトリ内
- それ以外（レポート・要約・エクスポート・画像）→ `~/Desktop/claude-outputs/<category>/`
- 新カテゴリ: `mkdir -p` でサブディレクトリ作成後に書き出す
- `~/Desktop/` 直下散乱禁止

## プロジェクトメモリ管理（全プロジェクト・全セッションに適用）

### 更新タイミング

- **セッション中（動的）**: 重要な発見があった時点で即座に保存する
  - 対象: バグの根本原因、アーキテクチャ決定、ハマりポイント、検証済みパターン、動かないもの
  - 自明でない・コードを読んでも分からない知識のみ保存（コードパターン・ファイルパス等は除く）
- **セッション終了時**: 最終スイープ — 保存し忘れた重要事項がないか確認して保存

### セッション開始時のgit監査

1. `git log --oneline` で他ユーザーのコミットを確認
2. 他ユーザーのコミットがある場合: 変更ファイルを特定し、関連メモリエントリと照合
3. 古くなったエントリを無効化・更新してから作業開始
4. 遅延フォールバック: メモリエントリのファイル/関数を参照する前に必ず存在確認。古いと判明したら即更新

### コードとメモリの競合

**現在のコードが常に正。メモリは参考。**

- メモリがコードと矛盾する場合: コードを信頼し、メモリを即座に更新
- 「メモリにXと書いてある」≠「Xが今も正しい」。必ず実態を確認してから主張する

### メモリの削除ルール

- **削除**: 内容が完全に間違い、または該当コード/機能が削除済みの場合
- **更新**: 部分的に古い・変化があった場合（削除より更新を優先）
- MEMORY.md のインデックスエントリも同時に削除/更新すること

### メモリのフォーマット規約

**メモリファイルはキャベマン圧縮形式で書く（ロスレス）。**
MEMORY.md は毎セッション読み込まれるため、密度が高いほどトークン効率が良い。

- フィラー・丁寧語・冠詞を排除して密度を上げる
- 技術的事実・数値・パス・関数名・エラー文・因果関係・順序・警告・制約は全て保持
- コード・コミット・PR本文は圧縮しない

**各プロジェクトメモリエントリに日付・タイムラインを記録する:**

```markdown
---
name: ...
description: ...
type: project | feedback | user | reference
created: YYYY-MM-DD
last_verified: YYYY-MM-DD   ← コードで確認した最終日
---
```

- `created`: 初回保存日
- `last_verified`: 実際にコード/動作で内容を確認した最終日（メモリ更新日ではなく検証日）
- コードrefを含むエントリは `last_verified` が30日超で要再検証フラグ

### キャベマン圧縮のルール（全デバイス・全出力に適用）

**キャベマン圧縮は常にロスレス（無損失）でなければならない。**

- 削除して良いもの: 冠詞・フィラーワード・丁寧語・ヘッジング表現
- 削除してはいけないもの: 技術的事実・数値・ファイルパス・関数名・エラーメッセージ・因果関係・手順の順序・警告・制約条件
- メモリファイルへの圧縮: 全情報を保持したまま密度を上げる。情報の欠落は禁止
- コード・コミット・PR本文: 圧縮しない（そのまま書く）
